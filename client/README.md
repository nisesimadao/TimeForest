# TimeForest — デスクトップクライアント

TimeForest のデスクトップ版は Electron で実装しています。
Chrome 拡張が TimeTree Web の UI へ機能を追加するのに対し、デスクトップ版は独自のカレンダー UI を提供します。

```bash
cd client
npm install
npm start          # 開発時は npm run dev（DevTools 付き）
```

初回起動時は TimeTree のログイン画面を表示します。
ログイン後のセッションはアカウントごとに保持します。

## TimeTree Web との主な違い

| 項目 | TimeTree Web | TimeForest |
| --- | --- | --- |
| アジェンダ | なし | 今日以降を一つのリストで表示 |
| 月セルからあふれる予定 | 一部が非表示 | `+N 件` を表示し、その日のアジェンダへ移動可能 |
| 複数カレンダー | 個別に切り替え | 一つの一覧へ統合し、ミラーは重複排除 |
| 検索 | 範囲が限定的 | 読み込み済みイベントをローカル検索 |
| 週表示 | 時間グリッド | 時間グリッド。重複予定を横並びで配置 |
| 予定詳細 | モーダル | 対象行を基準にしたポップオーバー |
| コマンドパレット | なし | `Ctrl+K` |
| テーマ | 固定 | Light / Dark / System |
| エクスポート | なし | Markdown / CSV / JSON / ICS |
| アカウント切り替え | 再ログインが必要 | アカウントごとのセッションを保持して切り替え |

## アカウント切り替え

サイドバー左上のアカウント名をクリックするか、`Ctrl+K` から「アカウント」を選択します。

アカウントごとに `persist:tt-<id>` パーティションを作成し、Cookie を分離します。
切り替え時は使用する Electron session を変更し、イベント、ラベル、メンバー、祝日、表示設定を破棄してから対象アカウントのデータを読み直します。

この分離により、あるアカウントの Cookie を別のアカウントの API リクエストへ付けない構成にしています。
単一アカウント時代の既存セッションは、初回起動時に取り込みます。

## キーボード

| キー | 動作 |
| --- | --- |
| `Ctrl+K` / `/` | コマンドパレットを開く |
| `←` `→` | 前 / 次へ移動。週表示では 1 週、それ以外では 1 か月 |
| `T` | 今日へ移動 |
| `1` `2` `3` | アジェンダ / 週 / 月を切り替える |
| `Esc` | 開いている UI を閉じる |

コマンドパレットでは、`7/20`、`2026-07-20`、`7月20日`、`明日`、`今日` などの日付表現を解釈します。

## 設計

### 認証

`main.js` は TimeTree のログインページを BrowserWindow で開きます。
ユーザーは TimeTree 側でメール、Apple、Google、Facebook などの方法を使ってログインします。
TimeTree が発行した Cookie は、そのアカウント専用の Electron partition に保存します。

TimeForest はパスワードを受け取りません。
API 呼び出しでは HTML 内の CSRF token と、TimeTree が保存したセッション Cookie を使用します。

User-Agent は、Electron の標準文字列ではなく、同梱 Chromium と同世代の Chrome として送信します。
TimeTree のログインページが Electron の標準 User-Agent を未対応ブラウザとして扱うためです。

### API 通信

レンダラーは `file://` から動作するため、`timetreeapp.com` の API へ直接アクセスすると CORS の制約を受けます。
そのため、API リクエストはメインプロセスの `session.fetch()` を経由します。
IPC から許可するパスは `/api/*` に限定しています。

`net.fetch` は使用しません。
アカウントごとの partition を明示した通信を維持するため、認証付き API 通信は `apiFetch()` へ集約しています。

### データ保持

起動時に対象カレンダーのイベントを取得し、表示中はメモリに保持します。
アジェンダ、月表示、検索は、読み込み済みデータをローカルで計算します。

### 共有ロジック

デスクトップ版は `../src/lib/*` を直接読み込みます。
別コピーは持ちません。

- `tz.js`：終日予定と時刻付き予定の日時処理。
- `recur.js`：RRULE / EXDATE の展開。
- `api.js`：`setTransport()` で通信層を差し替え可能な API クライアント。
- `model.js`：TimeTree のイベントデータを表示用 occurrence へ変換。
- `export.js`：Markdown / CSV / JSON / ICS の出力。

### モーション

View Transitions API を使用します。

- 前後の月移動では、時間方向に対応したスライドを使います。
- ビュー切り替えは短いクロスフェードにします。
- テーマ変更は transition callback 内で `data-theme` を変更します。
- 連続操作で transition が中断されても後処理が残るよう、AbortError を考慮します。
- `prefers-reduced-motion` を尊重します。

主な easing は `cubic-bezier(0.32, 0.72, 0, 1)`、時間は 180〜260 ms です。

## 既知の制限

- TimeTree の内部 API に依存するため、TimeTree 側の変更で動作しなくなる可能性があります。
- RRULE の日時処理は JST / UTC の固定オフセットを主対象としており、DST の遷移をまたぐ場合は 1 時間ずれる可能性があります。
- 通知はアプリが起動している間だけ動作します。トレイ常駐には対応していますが、TimeTree 本体のサーバープッシュとは異なります。

予定の作成、編集、削除、繰り返し、コメント、リマインド通知、electron-builder によるパッケージングは実装済みです。
全体のセットアップと配布方法はルートの [README](../README.md) を参照してください。
