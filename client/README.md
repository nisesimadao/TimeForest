# TimeForest — デスクトップクライアント

Electron 製。TimeTree の Web/アプリに無いものを足すのではなく、**最初からそれ前提で
組み直したクライアント**。

```
cd client
npm install
npm start          # 開発時は npm run dev（DevTools 付き）
```

初回はログイン画面が出る。以降はセッションが保持される。

## 本家に無いもの

| | 本家 | これ |
| --- | --- | --- |
| アジェンダ表示 | 無い | 3ヶ月ぶんを1本のリストで縦読み |
| 月セルに入り切らない予定 | **黙って捨てる** | `+N 件` と数えて出す。押すとその日のアジェンダへ |
| 複数カレンダー | 切り替え | 1つのリストに統合（ミラーは重複排除） |
| 検索 | 限定的 | 全期間を即時。全部メモリ上にあるので待ち時間ゼロ |
| 週表示 | 時間グリッド | 時間グリッド。重なる予定を横並びに配置 |
| 予定の詳細 | モーダル | クリックした行から生えるポップオーバー |
| コマンドパレット | 無い | `Ctrl+K`。検索・日付移動・全コマンド |
| ダークモード | 無い | ライト / ダーク / システム追従 |
| 書き出し | 無い | Markdown / CSV / JSON / ICS |
| アカウント切り替え | 再ログインが必要 | 常時ログイン済みのまま即座に切り替え |

## アカウント切り替え

サイドバー左上のアカウント名をクリック（または `Ctrl+K` →「アカウント」）。

**アカウントごとに独立した Cookie ジャー**（`persist:tt-<id>` パーティション）を
持つ。切り替えはどのパーティションに話しかけるかを変えるだけなので、ログアウトも
再ログインも要らないし、あるアカウントのセッションが別のアカウントのリクエストに
混ざりようがない。

セッションが本当に分離されていることは、追加時のログイン画面が既存アカウントで
自動ログインせず**素のサインインフォームを出す**ことで確認できる（検証済み）。
アカウントを切り替えると、イベント・ラベル・メンバー・祝日・カレンダー表示設定を
すべて破棄してから読み直す。前のアカウントのカレンダー ID が1つでも残ると、
別人のデータを新しいアカウントの名前で表示してしまうため。

単一アカウント時代のセッションは初回起動時に自動で取り込む（再ログイン不要）。

## キーボード

| キー | |
| --- | --- |
| `Ctrl+K` / `/` | コマンドパレット |
| `←` `→` | 前 / 次（週表示なら1週、それ以外は1ヶ月） |
| `T` | 今日 |
| `1` `2` `3` | アジェンダ / 週 / 月 |

パレットは日付を解釈する: `7/20` `2026-07-20` `7月20日` `明日` `今日` など。

## 設計

### 認証 — パスワードはこのアプリを通らない

`main.js` が TimeTree の**公式ログイン画面**を普通の BrowserWindow で開くだけ。
ユーザーはそこで（メール / Apple / Google / Facebook のどれでも）サインインし、
TimeTree が自分のセッション Cookie をそのアカウントのパーティションに置く。
アプリが読むのは HTML 中の CSRF トークンだけで、認証情報には一切触れない。

UA は Electron のデフォルトではなく普通の Chrome を名乗る。素のままだと TimeTree が
自分のログイン画面の上に「お使いのブラウザはサポートされていません」の帯を出すため
（新規ユーザーが最初に見るものがそれになる）。同世代の Chromium が同じページを
描画しているのだから、そう名乗る方が正確でもある。

### CORS — レンダラは API を直接叩けない

レンダラは `file://` なので `timetreeapp.com` へは CORS で弾かれる。API 呼び出しは
すべてメインプロセスの `session.fetch()` を経由する（IPC 越し、`/api/*` のみ許可）。
これで Cookie も付き、CORS も無い。

> **落とし穴**: `net.fetch` は使えない。`session` オプションを黙って無視して**常に
> デフォルトセッション**を使うため、ログイン済みでも Cookie が空のジャーを見て
> 「未ログイン」を返し続ける。必ず `session.fetch()` を使うこと。
> アカウントごとにパーティションを分けた今、この罠は「混乱する」では済まず
> **別アカウントのデータを引く**事故になり得るので、経路は `apiFetch()` 一本に
> 集約してある。

### データ — 全部持ってきて全部メモリに置く

TimeTree の全履歴は約 2400 件・8 チャンクで取り切れる。小さい。なので起動時に
全部引いてメモリに置き、アジェンダも月表示も検索もすべてローカルの純粋計算にした。
本家が毎回サーバーに問い合わせるところで、こちらは待たない。これが体感速度の正体。

### ロジックは拡張と共有

`../src/lib/*` を `<script>` でそのまま読む。コピーしない。

- `tz.js` — 終日は UTC / 時刻付きは Asia/Tokyo
- `recur.js` — RRULE + EXDATE 展開器
- `api.js` — `setTransport()` で通信層を差し替え可能にしてある（拡張は直 fetch、
  ここは IPC 経由）
- `model.js` — 生イベント → 日付つき occurrence。TimeTree のデータモデルの罠は
  ここに全部書いてある（メモ = category 2、誕生日 = type 1、終日 end_at は inclusive 等）
- `export.js` — MD / CSV / JSON / ICS

### モーション

`View Transitions API`。方向に意味を持たせてある:

- **翌月 → 右から入る / 前月 → 左から入る**。タイムライン上の移動として読める。
  ここを逆にすると、アニメーション無しより悪い
- **ビュー切り替えは移動ではなく「レンズの切り替え」**なのでスライドさせず、
  短いクロスディゾルブのみ
- **テーマ変更**は `data-theme` の書き換えをトランジションの**コールバック内**で
  やる。先に書き換えると「変更後の色」でスナップショットが撮られ、溶ける先が無く
  なって一瞬で切り替わってしまう
- 走行中に次のトランジションを始めると前のは中断され、`finished` が
  **AbortError で reject する**。`.finally()` は再 throw するので、成否どちらでも
  後始末する形にしてある（連打で壊れない）
- `prefers-reduced-motion` は全て尊重

カーブは iOS 準拠の `cubic-bezier(0.32, 0.72, 0, 1)` / 180〜260ms。

## 既知の制限

- 内部 API 依存。TimeTree が仕様を変えれば壊れる。公式 API ではないし、自分の
  アカウントの自分のデータを個人的に読み書きする用途を想定
- RRULE 展開は固定オフセットのゾーン（JST / UTC）で正確。DST のあるゾーンでは
  遷移をまたぐと1時間ずれ得る
- 通知はアプリ起動中のみ鳴る（トレイに常駐して受ける。TimeTree のサーバー自身も
  スマホに push するので、閉じている間はそちらが届く）

（かつてここに並んでいた「読み取り専用 / 通知未実装 / パッケージ化未設定」は
いずれも解消済み。予定の作成・編集・削除、繰り返し、コメント、リマインド通知、
electron-builder でのパッケージングはすべて実装済み。詳細はルートの README。）
